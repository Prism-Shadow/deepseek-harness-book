# 01 研究说明：是否引入 AI 代码助手

> 本文档仅用于明确研究范围与待确认信息，不含任何研究结论。

## 一、研究目标

回答一个决策问题：**一家约 200 人、主要在中国开展业务的软件公司，是否应在未来 12 个月内为研发团队引入 AI 代码助手。**

具体而言，本研究需要产出：

1. 对"引入"与"不引入"两种路径的成本、收益与风险做可比较的评估；
2. 若引入，明确推荐的产品形态、试点范围与推广节奏；
3. 给出可执行的落地建议（选型、试点、衡量指标、退出条件）；
4. 明确本研究的前提假设与信息缺口，供决策层补充确认。

## 二、公司当前已知情况

目前仅确认以下有限信息，其余情况待调研补充：

- **公司规模**：约 200 人。
- **业务地域**：主要在中国开展业务（隐含中国境内数据合规、网络环境、支付与采购方式等约束）。
- **行业**：软件公司，存在研发团队（研发团队规模、技术栈、组织方式未知）。

## 三、需要比较的选择

| 编号 | 方案 | 说明 |
| --- | --- | --- |
| A | 不引入，维持现状 | 作为基准线，评估工具引入的净增量价值 |
| B | 引入商业 AI 代码助手（国际产品） | 如 GitHub Copilot 等，需评估国内访问、计费与合规问题 |
| C | 引入商业 AI 代码助手（国内产品） | 如通义灵码、文心快码、CodeGeeX 等，需评估能力、数据政策与锁定风险 |
| D | 私有化 / 自建方案 | 基于开源模型或本地部署，需评估成本、维护能力与效果差距 |
| E | 先试点后推广 | 小范围验证再决定是否全面铺开（可与 B/C/D 组合，作为引入节奏的选择） |

比较维度（初稿，可调整）：

- 提效收益：编码加速、代码补全/生成质量、对团队实际工作流的贴合度；
- 成本：订阅/部署费用、培训与推广成本、维护成本；
- 风险：数据安全与合规（中国境内法规、代码出境）、供应链与依赖风险、员工接受度；
- 落地难度：现有开发工具链集成、网络环境、采购流程、试点周期。

## 四、仍需确认的问题

### 1. 研发团队与工作方式

- 研发团队规模、人员构成（前后端、算法、测试等）？
- 主要技术栈与开发语言？
- 代码托管在何处（本地 GitLab、Gitee、GitHub 等）？是否允许代码离开公司网络？
- 现有开发流程（需求、评审、CI/CD）成熟度如何？

### 2. 业务与数据约束

- 是否存在强监管行业背景（金融、政务、医疗等）？是否有数据出境或本地化要求？
- 对代码、文档等敏感信息的保密等级要求？
- 是否已有数据合规负责人或制度？

### 3. 预算与决策机制

- 未来 12 个月研发工具的预算规模？
- 引入工具的决策人是谁（CTO、研发负责人、IT 部门）？
- 决策时间表是否有硬性要求？

### 4. 预期与衡量

- 引入 AI 代码助手的核心诉求是什么（提效、质量、留人、形象）？
- 管理层期望的投入产出周期与可量化指标？
- 公司对"效果不明显即停止"的容忍度（是否有退出预案）？

### 5. 外部环境

- 是否需要调研国内同规模公司、同行业的采用情况与公开案例？
- 是否需要关注监管政策（生成式 AI 相关法规）的变化？

## 五、后续步骤

1. 确认上述待确认问题；
2. 按问题清单开展桌面调研与（如可行）同行访谈；
3. 对方案 A–E 进行逐维度比较并给出建议；
4. 输出最终研究报告。
