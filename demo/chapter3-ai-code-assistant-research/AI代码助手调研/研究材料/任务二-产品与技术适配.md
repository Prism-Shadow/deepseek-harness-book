# 任务二：产品与技术适配研究

> 本材料服务于「AI 代码助手调研」项目（研究说明见 `01-研究说明.md`，任务定义见 `02-研究计划.md` 之「三、任务二」）。
> 调研时间：2026 年 8 月（材料中产品信息以抓取到的官方页面内容为准）。
> 来源数量：12 个（来源清单见文末）。所有标注「未核实」或「待确认」的内容均未获官方或可靠二手来源确认，不得当作事实陈述。

## 一、研究问题

按 `02-研究计划.md` 的任务定义，本材料回答以下四个问题：

1. **功能能力对比**：国际商业产品（GitHub Copilot 等）与国内商业产品（通义灵码、文心快码、CodeGeeX 等）在代码补全、对话生成、代码评审、测试生成、上下文理解等维度的能力差异；
2. **私有化 / 自建方案**：基于开源模型或本地部署的方案，其能力水平与维护要求（部署成本、硬件、运维人力）；
3. **技术栈与工具链适配**：各产品对主流技术栈（前端、后端、算法等常见语言）、IDE 与开发工具链（代码托管平台、CI/CD、代码评审流程）的适配情况；
4. **国内可用性与采购**：国内网络环境下各产品的可用性、访问方式（直连 / 代理 / 专属通道）与采购流程差异（开票、合同、计费方式）。

## 二、产品功能能力对比

### 2.1 国际商业产品：GitHub Copilot

GitHub Copilot 是 GitHub（微软）出品的 AI 编码助手，其官方功能文档列出的能力可归为四类 [来源 2]：

| 类别 | 能力 | 说明 |
| --- | --- | --- |
| 辅助功能 | 行内补全 | IDE 内自动完成式代码建议；VS Code、Xcode、Eclipse 还支持 next edit suggestions（预测下一步编辑位置） |
| 辅助功能 | Copilot Chat | 聊天界面，可在 GitHub 网站、GitHub Mobile、支持的 IDE、Windows Terminal 中使用，支持「技能」（skills） |
| 辅助功能 | PR 摘要 | 自动生成拉取请求变更摘要、受影响文件与评审关注点（GitHub.com 上） |
| 智能体功能 | Copilot CLI / Copilot App / cloud agent | 终端命令行助手；桌面代理应用（可并行多代理会话、定时任务）；云端自治代理（研究仓库、制定计划、改代码、开 PR） |
| 智能体功能 | Copilot code review | 在 GitHub.com 与 IDE 内提供 AI 代码评审建议（部分工具处于公开预览） |
| 智能体功能 | IDE 代理模式 | 在 IDE 内自主确定改动文件、给出代码变更与终端命令供用户批准 |
| 自定义 | Copilot Spaces / 自定义说明 / Memory / 提示文件 / MCP / 自定义代理 | 组织上下文、记忆仓库信息、接入外部工具（MCP）等 |
| 管理 | 策略管理、访问管理、使用数据、审计日志、文件排除 | 面向 Copilot Business / Enterprise 的企业管理能力 |

**模型生态**：Copilot 在模型下拉列表中提供多家模型（Anthropic Claude 系列、OpenAI GPT 系列、Google Gemini、xAI Grok、Kimi、微软 MAI-Code 等），用户可按功能与场景选择 [来源 3]。这使其对话与智能体能力不绑定单一模型，模型清单随市场变化较快，具体可用范围以订阅计划为准。

**定价（官方定价页）[来源 3][来源 4]**：

- 个人：Free（0 美元，含 2,000 次补全/月及有限 Chat/agent 用量）、Pro（10 美元/月）、Pro+（39 美元/月）、Max（100 美元/月）；高级功能（cloud agent、code review、第三方 agent 等）随计划档位解锁，并配每月 AI credits 额度（Pro 15 美元、Pro+ 70 美元、Max 200 美元）。
- 组织/企业：Copilot Business 19 美元/用户/月（每用户含 1,900 AI credits）；Copilot Enterprise 39 美元/用户/月（每用户 3,900 credits，仅限 GitHub Enterprise Cloud）。超出资源池按 0.01 美元/AI credit 收费；**代码补全与 next edit suggestions 不计入 credits，付费套餐内不限次数** [来源 4]。
- 数据驻留：使用 GitHub Enterprise Cloud 的组织可对 Copilot 强制实施地理数据驻留 [来源 1]。

**代码评审能力定位**：Copilot 的「代码评审」是平台级能力（对 github.com 上的全部 PR 提供评审，即使作者无 Copilot 许可也可由组织开启并计费），与 GitHub 平台深度绑定；IDE 内也有 diff 评审 [来源 3][来源 4]。这一点在「工具链适配」部分再展开。

### 2.2 国内商业产品

#### 2.2.1 通义灵码（现名 Qoder CN，阿里云）

通义灵码（Lingma）已于 2026 年 5 月 20 日正式更名为 **Qoder CN**，官方文档明确「在其他渠道看到『通义灵码』相关内容，与本产品为同一产品」[来源 5]。核心能力 [来源 5]：

- **代码补全**：基于跨文件上下文生成行级/函数级代码、单元测试、代码优化建议；注释生成代码。
- **智能问答**：研发问题问答、工程问答（结合当前仓库理解）、图片多模态问答、企业知识库问答。
- **文件编辑（Edit Mode）**：多文件代码修改、多次迭代、快照回滚、代码审查。
- **编程智能体（Agent Mode）**：自主决策、工具使用（文件读写、语义检索、终端命令执行）、支持 MCP 工具配置，端到端完成编码任务。
- **模型选择器**：支持 GLM、DeepSeek、Kimi、MiniMax 等国内主流大模型，按场景/语言/任务复杂度切换 [来源 5]。
- **专家团 / Quest 2.0 / Repowiki / Subagent**：面向前后端、数据库、运维、测试等领域的专家智能体；任务规划拆解、工程级知识库、子智能体协作。
- **企业级能力**：统一授权管理、统计报表、知识管理（企业知识库问答、基于企业代码库的生成增强）、自定义扩展管理；企业 VPC 版支持专属 VPC 部署与内网连接 [来源 5][来源 6]。

#### 2.2.3 CodeGeeX（智谱 AI）

CodeGeeX 是智谱 AI × 清华大学联合研发的代码生成大模型及编程助手，企业版使用手册（V4.8）给出如下信息 [来源 8]：

- **功能**：代码生成与补全、智能问答（含 /explain、/comment、/fixbug、/tests、/optimize 快捷指令）、单元测试生成、代码翻译、代码注释、交互式编程。
- **企业版亮点**：基于企业自有业务代码的**模型微调**、检索增强生成（RAG，基于 @repo 对企业代码库问答，降低幻觉）、**本地私有化部署**、企业级管理后台、支持 SSO。

**个人版定价**：本次调研未获取到 CodeGeeX 个人版官方定价页；第三方横评文章称其个人版「完全免费、靠社区捐赠」[来源 10]，该信息**未核实**，需以官方为准。

## 三、私有化 / 自建方案

私有化 / 自建指企业自行部署开源模型与开源工具（或购买国内厂商私有化版），代码不出内网。综合第三方部署指南 [来源 9] 与各厂商私有化产品信息 [来源 7][来源 8] 整理如下。

### 3.1 开源工具形态对比 [来源 9]

| 工具 | 形态 | 模型服务 | IDE 支持 | 多用户 | 适用场景 |
| --- | --- | --- | --- | --- | --- |
| Tabby | 全栈（模型服务 + IDE 插件 + 认证 + 遥测一体） | 自带推理运行时 | VS Code、JetBrains | 支持（团队认证、按用户 API Key、用量统计） | 想直接替代 Copilot 的团队；绑定 Tabby 支持的模型清单（覆盖主流 Qwen、DeepSeek 变体） |
| Continue | 仅 IDE 插件 | 不自带，接 vLLM/Ollama/云 API（OpenAI 兼容） | VS Code、JetBrains | 通过后端实现 | 已有 vLLM 等推理栈的团队；需自建认证与遥测 |
| FauxPilot | 全栈（兼容 Copilot API） | Triton 推理服务器 | VS Code | 有限 | 兼容旧 Copilot 插件；**2023 年后无重大更新，不推荐新部署** |
| Kilo | 智能体编程平台 | 不自带，接任意 OpenAI 兼容 API | VS Code、JetBrains、CLI | 通过后端实现 | 已有推理后端、需要 agentic 工作流（多文件修改、终端命令）的团队 |

### 3.2 可自建的开源代码模型（HumanEval pass@1 与显存需求）[来源 9]

| 模型 | HumanEval | 参数量 | VRAM（FP16） | VRAM（4-bit） |
| --- | --- | --- | --- | --- |
| Qwen2.5-Coder 32B | 92.7% | 32B | ~65GB | ~20GB |
| Qwen2.5-Coder 14B | 89.6% | 14B | ~29GB | ~9GB |
| Qwen2.5-Coder 7B | 88.4% | 7B | ~15GB | ~5GB |
| DeepSeek-Coder-V2-Lite | 81.1% | 16B MoE | ~20GB | ~8GB |
| DeepSeek-Coder-V2 236B | ~90% | 236B MoE | 需 4×H100/A100（最低） | — |
| StarCoder 2 15B | 72.6% | 15B | ~30GB | ~10GB |

要点 [来源 9]：

- **补全延迟比准确率更关键**：自动补全实际使用 fill-in-the-middle（FIM）能力，7B/14B 模型在共享节点上更易达到补全延迟目标；32B 多文件理解更好。
- 该来源称 Qwen2.5-Coder 在 2026 年初成为自托管编码模型中最广泛部署的模型（依据 RunPod 部署数据），此说法来自第三方，**未核实**。

### 3.3 成本与维护要求

**成本数学（示例，来自第三方部署指南 [来源 9]）**：以按小时租用的 A100 80GB（约 1.04 美元/小时，约 749 美元/月）为例，对比 Copilot Business 19 美元/席位/月，**约 39 个席位时自建与订阅成本打平**；单个 A100 节点可服务 15–25 个并发补全请求（Tabby 请求排队），团队越大每席位成本越低。**注意：该算例为第三方服务商（Spheron）以自身 GPU 租用价格为基准的估算，硬件价格、模型与并发假设会显著改变结论，仅作量级参考。**

**维护要求**：

- **全栈工具（Tabby）**：自带模型服务、认证、遥测，运维负担相对低；约束是模型清单受限、需跟随其发布节奏 [来源 9]。
- **插件 + 自建推理（Continue 等）**：需自行运维推理服务（vLLM/Ollama）、补全认证与遥测，适合已有运维能力与 GPU 的团队 [来源 9]。
- **大模型（如 DeepSeek-Coder-V2 236B）**：至少 4×H100/A100 起步，涉及多机推理、显存调度，运维复杂度显著上升 [来源 9]。
- **国内厂商私有化版**：文心快码企业专属版（2,500 元/人/年、100 人起购、含模型私有化部署）与 CodeGeeX 企业版（私有化部署 + 管理后台 + 微调）由厂商提供部署与支持，运维人力由厂商分担，但起购门槛高（文心 100 人）、报价需商务洽谈 [来源 7][来源 8]。
- **运维人力**：开源自建通常需要至少具备 GPU 集群/推理服务运维能力的工程师；具体人力投入（FTE 数量）各来源均未给出量化数据，**待确认**。

## 四、技术栈与工具链适配

### 4.1 语言与 IDE 适配

**GitHub Copilot [来源 1][来源 3]**：

- 语言：基于公开仓库训练，「对所有出现在公共仓库中的语言」提供建议，质量取决于训练数据量（官方明示 JavaScript 是支持最好的语言之一，小众语言建议较少）。
- IDE：VS Code、Visual Studio、JetBrains IDEs、Xcode、Neovim、Eclipse、Raycast、SQL Server Management Studio、Zed；另有 GitHub CLI（终端）、Windows Terminal（聊天）、GitHub Mobile、GitHub.com 网页端。**注意：官方 FAQ 曾指出聊天功能仅限 VS Code、JetBrains、Visual Studio 等部分扩展** [来源 1]，与定价页的平台列表需结合看（定价页列举的是「受支持环境」的完整集合）[来源 3]。

**Qoder CN（通义灵码）[来源 5]**：支持 Java、Python、Go、C#、C/C++、JavaScript、TypeScript、PHP、Ruby、Rust、Scala、Kotlin 等主流语言；IDE 支持 JetBrains 全家桶（2020.3+）、VS Code（1.68.0+）、自研 Qoder CN IDE（Windows 10/11、macOS 11+）、Remote SSH/WSL 远程开发、VS Code WebIDE（Open VSX 市场）、HUAWEI DevEco Studio。

**文心快码 [来源 7]**：IDE 支持 VS Code、JetBrains、Visual Studio、Xcode、CLI 与自研 Comate AI IDE。官方文档未给出完整语言清单，**待确认**。

**CodeGeeX [来源 8]**：300+ 种语言，30 种主流语言效果更好（前端含 Vue，后端含 Java/Python/Go/C#/C++/Rust/Scala/SQL 等，APP 含 Swift/Objective-C）；IDE 支持 VS Code、JetBrains 全家桶，操作系统含麒麟、统信等国产化系统。

**对主流技术栈的覆盖判断（综合官方文档）**：

- 前端（JavaScript/TypeScript/Vue）：四家均覆盖；Copilot 对 JS/TS 官方明示效果最佳 [来源 1]；CodeGeeX 明确列出 Vue [来源 8]。
- 后端（Java/Python/Go/C#/C++/PHP/Ruby/Rust/Scala/Kotlin）：四家官方文档均覆盖，其中 Qoder 与 CodeGeeX 给出了明确语言清单 [来源 5][来源 8]。
- 算法/数据（Python、SQL）：均支持；开源自建侧 Qwen2.5-Coder、DeepSeek-Coder 在代码生成基准上表现靠前 [来源 9]。
- 移动端（Swift/Kotlin）：Copilot 支持 Xcode、CodeGeeX 支持 Swift/Objective-C 与 Kotlin [来源 1][来源 8]。
- 国产化环境（麒麟/统信）：CodeGeeX 明确支持 [来源 8]；其余产品未在官方文档中见明确说明（待确认）。

### 4.2 代码托管、CI/CD 与代码评审流程

**GitHub Copilot 与 GitHub 平台深度绑定 [来源 2][来源 3][来源 4]**：

- 代码托管：PR 摘要、cloud agent（开 PR）、Copilot code review 均运行在 github.com 上；企业版还提供企业代码库索引（Enterprise 计划）。
- CI/CD：官方计费 FAQ 提到「自 2026 年 6 月 1 日起，code review 工作流消耗 GitHub Actions 分钟数」[来源 3]，即评审流程与 GitHub Actions 计费打通。
- 评审流程：Copilot code review 可覆盖组织内所有 PR（含无许可用户），由管理员策略开关控制 [来源 3]。**对国内常见托管平台（GitLab CE 自建、Gitee、CODING 等）无官方原生集成说明，需代理改造或人工搬运，待确认。**

**国内产品与国内工具链的适配**：

- CodeGeeX 企业版明确支持对接 GitLab、Gitee 三方功能调用 [来源 8]。
- Qoder CN（阿里云）与文心快码均隶属国内云厂商生态（阿里云、百度智能云），与各自云体系（云效、百度智能云产品）的集成方式在官方文档中可见线索（如 Qoder 通过云效/阿里云控制台下单、知识管理与统计报表）[来源 6][来源 7]，但**与具体 CI/CD 流水线（Jenkins、GitLab CI 等）的集成细节未在本次抓取的官方文档中明确，待确认**。
- 国内产品普遍具备企业控制台（用户管理、统计报表、知识管理），便于在 GitLab/Gitee 托管 + 自建 CI 的典型国内研发环境中落地，但「AI 评审接入现有 MR/PR 评审流程」的能力（如自动评论 MR）各产品公开资料有限，**待确认**。

## 五、国内网络可用性与采购流程

### 5.1 网络可用性与访问方式

- **GitHub Copilot（国际）**：Copilot 服务位于境外，中国大陆直连通常不稳定。第三方文章（2025-09-21）记录：Copilot 模型下拉列表中的 Claude 模型在中国大陆用户处消失，挂代理后恢复，作者判断是模型厂商（Anthropic）限制中国区访问 [来源 11]。这说明：① 在中国大陆使用 Copilot 一般需要代理等网络手段；② 即使 Copilot 本体可用，其内置的部分第三方模型也可能对中国区不可用 [来源 11]。**Copilot 官方文档未对中国大陆可用性作正式说明，以上为第三方观察，仍需以实际网络与账号环境验证（待确认）。** Copilot 免费档（Free）即可用基础补全 [来源 3]，可用于小范围网络连通性验证。
- **国内产品（Qoder CN、文心快码、CodeGeeX）**：服务部署于国内，通常可直连。Qoder CN 企业 VPC 版支持专属 VPC 部署与内网连接（满足数据不出内网的需求）[来源 5][来源 6]；CodeGeeX 企业版本身即私有化部署形态 [来源 8]；文心快码企业专属版含模型私有化部署 [来源 7]——这些属于「专属通道/内网直连」形态。
