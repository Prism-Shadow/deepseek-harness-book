# 《从零开始玩转 DeepSeek Harness》写作规范

## 写作目标

第一部分是一组可以照着完成的实战。每章都要让读者得到一个可见结果，并能根据截图确认自己是否做对。

## Markdown 文件

- 每章写在对应的 `book/chapterN.md` 中。
- 章标题使用一级标题，节标题使用二级标题，并保留模板中的标题 ID。
- 目录已经确定的标题直接沿用，不自行改名或增加一级、二级标题。
- 节内可以使用三级标题整理较长的操作过程。

## 实战写法

按照读者实际操作的顺序写。每一步先说明要做什么，再给出操作或命令，随后展示读者应该看到的界面和结果。遇到权限确认、模型选择、文件修改等容易出错的地方，紧跟一条简短提醒。

文字只承担截图无法表达的内容。不要大段介绍背景，也不要把界面上已经写明的文字重新抄一遍。

## 截图要求

- 安装完成、关键按钮、重要配置、运行过程和最终结果尽量截图。
- 一张截图只说明当前步骤需要读者观察的内容，裁掉无关区域。
- 截图保持清晰，不拉伸，不使用聊天软件二次压缩后的图片。
- 图片放入 `book/assets/chapterN/`，文件名使用 `N-M-序号-内容.png`，例如 `1-1-01-install.png`。
- Markdown 使用相对路径和有意义的说明文字，例如 `![DSH 安装完成后的首页](assets/chapter1/1-1-01-install.png)`。
- 截图前隐藏 API Key、访问令牌、个人文件路径、内部网址和聊天内容。

## SVG 配图提示词

使用下列提示词绘制结构图、流程图和状态图：

```text
绘制「[NAME]」专业结构图。保留可编辑的 SVG 源文件，并按原画布尺寸导出同名 PNG 供书稿引用。

内容目标：
- 图中只表达一个核心结论：[KEY_MESSAGE]。
- 必须包含这些节点：[NODES]。
- 必须表达这些关系：[RELATIONSHIPS]。
- 使用精确的专业术语，不使用含糊、装饰性或营销化文案。

版式与构图：
- 画布比例 16:9，使用 viewBox="0 0 1600 900"。
- 留足四周空白，元素对齐，间距均匀；任何文字、色块、连线和箭头不得重叠。
- 按从左到右或从上到下的单一阅读方向排列，最多使用两层信息。
- 每个节点仅保留短标题和一行说明，避免拥挤。
- 连线使用深蓝灰色实线；只有异常、回退或可选路径使用虚线。

视觉风格：
- 专业、明亮、克制，适合中文技术书稿；使用纯白色背景，避免大面积冷灰蓝色。
- 使用“湛蓝强调 + 中性灰承载”的配色：核心节点使用湛蓝 #315EF5 和白色文字，主路径与重要边框使用湛蓝 #315EF5，浅蓝填充使用 #EEF2FF。普通节点使用浅灰 #F3F4F6，灰色边框使用 #9AA7B8，正文使用 #273142。
- 不要把所有节点和线框都画成蓝色。湛蓝只用于当前执行节点、核心组件和主数据流；其余结构使用灰色线框，形成明确的视觉层级。
- 不使用渐变、阴影、3D 效果、高饱和色、卡通插画或无关图标。
- 标题字号 46–52 px，节点标题 28–32 px，说明文字 22–26 px；宁可减少文字，不缩小字号。
- 中文使用 SimSun 或 Songti SC，英文使用 Times New Roman。

输出约束：
- 不使用数学公式。
- 所有文字必须是 SVG <text> 元素，不得转为路径或嵌入位图。
- 图形使用基础矢量元素，保持边缘清晰，线宽和圆角一致。
- 输出完整、可独立打开的 SVG，不附加解释性文字。
- 将 SVG 按 1600×900 像素渲染为同名 PNG，不裁切、不添加额外留白，不改变 16:9 比例。
```

SVG 作为可编辑源文件保留，完成后按原画布尺寸导出同名 PNG。书稿正文优先引用 PNG，不直接引用 SVG。

## 提交前检查

1. 从头按照正文重新操作一遍，确认步骤没有缺失。
2. 检查每张截图与前后文字对应，图片路径能够正常打开。
3. 删除无关解释和重复说明，让读者主要跟着操作和截图前进。
4. 确认没有提交密钥、账号信息或公司内部数据。
5. 运行 `./scripts/build_pdf.sh`，确认书稿能够生成 PDF。
