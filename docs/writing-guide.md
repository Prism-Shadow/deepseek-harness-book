# 《从零开始玩转 DeepSeek Harness》写作规范

## 写作目标

第一部分是一组可以照着完成的实战。每章都要让读者得到一个可见结果，并能根据截图确认自己是否做对。

## Markdown 文件

- 每章写在对应的 `book/chapterN.md` 中。
- 章标题使用一级标题，节标题使用二级标题，并保留模板中的标题 ID。
- 目录已经确定的标题直接沿用，不自行改名或增加一级、二级标题。
- 节内可以使用三级标题整理较长的操作过程。

## 实战写法

按照读者实际操作的顺序写。每一步先说明要做什么，再给出操作或命令，随后展示读者应该看到的界面和结果。遇到权限确认、模型选择、文件修改等容易出错的地方，紧跟一条简短提醒。

文字只承担截图无法表达的内容。不要大段介绍背景，也不要把界面上已经写明的文字重新抄一遍。

## 提示词格式

读者需要发送给 dsh 的提示词统一使用引用块。第一行使用红色的“提示词内容：”标题，空一行后写提示词原文：

```markdown
> <span class="prompt-title">提示词内容：</span>
>
> 你好，请用一句话介绍你自己
```

多段提示词的每一行都保留引用标记 `>`。文件树、终端命令、程序输出和错误信息仍使用对应的代码块，不添加“提示词内容：”标题。

## 截图要求

截图用于帮助读者找到入口、辨认关键状态或核对结果，不用于记录每一次点击。截图前先用一句话说明它要证明什么；没有明确答案，或者一句正文就能说清的操作，不必配图。

适合截图的内容包括难以寻找的操作入口、需要用户处理的审批状态、重要配置、文件或界面的实际变化，以及最终结果。普通的输入、发送、打开下拉框等动作通常直接写进正文。聊天回复只有在回复本身就是分析对象时才截图。

一张截图只承担一个主要任务，同时保留足够的界面上下文。裁剪时不得劈开文字、按钮、卡片、对话框边框、圆角或阴影，也不要只留下一个被放得很大的局部控件。前后对比图使用相同的窗口状态、裁剪范围和显示尺寸。

截图的采集、原图保存、裁剪、命名和清晰度要求见 [`book/assets/README.md`](../book/assets/README.md)。

## 截图与正文

截图应紧跟在产生该状态的操作或解释之后。正文先告诉读者要观察什么，图片负责给出可见证据，图后只解释不容易从画面直接判断的原因，不重复抄写界面文字。

Markdown 使用相对路径和描述可见结果的说明文字，例如：

```markdown
![dsh 完成模型调用并显示 token 统计](assets/chapter1/1-1-08-hello-reply.png){width=86%}
```

`width` 根据画面内容和页面观感决定，不为所有截图套用同一个比例。包含较多界面上下文的图片可以适当放宽；对话框、卡片等较小区域应保持接近真实界面的视觉尺度，不能为了占满版心而过度放大。对比图的宽度必须一致。排版系统只能把图片画布居中，不能修正图片内部不对称的白边，因此还要检查可见内容在画面中的位置。

修改或增加图片后运行 `./scripts/build_pdf.sh`。在 PDF 的 100% 视图下检查文字和细线是否清楚、图片是否显得过大、前后文字是否与图片分离，以及页面是否留下突兀的空白。发现问题时优先回到完整截图重新裁剪，不在 Markdown 中勉强放大一张范围不合适的图片。

## SVG 配图提示词

使用下列提示词绘制结构图、流程图和状态图：

```text
绘制「[NAME]」专业结构图。保留可编辑的 SVG 源文件，并按原画布尺寸导出同名 PNG 供书稿引用。

内容目标：
- 图中只表达一个核心结论：[KEY_MESSAGE]。
- 必须包含这些节点：[NODES]。
- 必须表达这些关系：[RELATIONSHIPS]。
- 使用精确的专业术语，不使用含糊、装饰性或营销化文案。

版式与构图：
- 画布比例 16:9，使用 viewBox="0 0 1600 900"。
- 留足四周空白，元素对齐，间距均匀；任何文字、色块、连线和箭头不得重叠。
- 按从左到右或从上到下的单一阅读方向排列，最多使用两层信息。
- 每个节点仅保留短标题和一行说明，避免拥挤。
- 连线使用深蓝灰色实线；只有异常、回退或可选路径使用虚线。

视觉风格：
- 专业、明亮、克制，适合中文技术书稿；使用纯白色背景，避免大面积冷灰蓝色。
- 使用“湛蓝强调 + 中性灰承载”的配色：核心节点使用湛蓝 #315EF5 和白色文字，主路径与重要边框使用湛蓝 #315EF5，浅蓝填充使用 #EEF2FF。普通节点使用浅灰 #F3F4F6，灰色边框使用 #9AA7B8，正文使用 #273142。
- 不要把所有节点和线框都画成蓝色。湛蓝只用于当前执行节点、核心组件和主数据流；其余结构使用灰色线框，形成明确的视觉层级。
- 不使用渐变、阴影、3D 效果、高饱和色、卡通插画或无关图标。
- 标题字号 46–52 px，节点标题 28–32 px，说明文字 22–26 px；宁可减少文字，不缩小字号。
- 中文使用 SimSun 或 Songti SC，英文使用 Times New Roman。

输出约束：
- 不使用数学公式。
- 所有文字必须是 SVG <text> 元素，不得转为路径或嵌入位图。
- 图形使用基础矢量元素，保持边缘清晰，线宽和圆角一致。
- 输出完整、可独立打开的 SVG，不附加解释性文字。
- 将 SVG 按 1600×900 像素渲染为同名 PNG，不裁切、不添加额外留白，不改变 16:9 比例。
```

SVG 作为可编辑源文件保留，完成后按原画布尺寸导出同名 PNG。书稿正文优先引用 PNG，不直接引用 SVG。

## 提交前检查

1. 从头按照正文重新操作一遍，确认步骤没有缺失。
2. 检查每张截图是否证明了正文提出的观察点，图片路径能够正常打开。
3. 删除无关解释和重复说明，让读者主要跟着操作和截图前进。
4. 确认没有提交密钥、账号信息或公司内部数据。
5. 确认本次新增或重拍的正文截图都有对应的完整截图，并且两者都不含敏感信息。
6. 运行 `./scripts/build_pdf.sh`，检查生成后的 PDF，而不只确认构建成功。
