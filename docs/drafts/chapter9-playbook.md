# 第 9 章实操手册（拍图用，非书稿）

正文在 `book/chapter9.md`，这份是抽出来的纯操作清单。所有截图存到 `book/assets/chapter9/`，文件名照下面写的存。截图前检查页面上没有 API Key、个人路径；JD 截图里的公司名和薪资是公开信息，可以保留，拿不准就打码。

## 第 0 步　准备

1. 在本机新建一个**空**文件夹 `job-hunt`（不要提前放文件，材料改为粘贴给 dsh 保存）。
2. 打开 dsh Web 端，**Add workspace** 选中 `job-hunt`，新建会话，确认 **Standard mode**。
3. 材料原文都在 `book/assets/chapter9/materials/`（共 5 个文件，没有简历，设定就是从没写过简历），下面各步直接从这些文件复制文本。

## 9.1　分析个人能力（8 张图）

### 开场几句话，让 dsh 开材料清单

发送：

```text
我是 2027 届市场营销专业本科生，暑假在一家宠物短视频公司做了两个月
兼职，现在准备秋招，目标是互联网公司的内容运营岗。接下来想让你帮我
盘点能力、调研岗位、写简历、模拟面试。先别开始做，列出你需要我提供
哪些材料，按重要性排。
```

- `9-1-01-material-list.png`　dsh 列出它需要的求职材料清单

清单里如果点到目标公司、岗位 JD、作品链接这类条目，不用管（8.2 才处理），下一步只交五份材料。

### 再把五份材料粘贴给 dsh 保存

注意：设定已改为没有初版简历（李小磊从没写过简历），材料只有五份。逐份发送，每份格式相同（开头一句 + 空行 + 该文件全文，全文从 materials/ 对应文件复制）：

```text
把下面的内容原样保存为 parttime-notes.md，一个字都不要改。

（此处粘贴 parttime-notes.md 全文）
```

- `9-1-02-save-notes.png`　第一份（兼职周记）保存成功，回复末尾带产物标签

依次保存其余四份，把文件名换成 transcript.md、project-report.md、activities.md、self-notes.md。全部存完发一句“列出工作区里现在的文件”。

- `9-1-03-files-ready.png`　dsh 列出工作区文件，五份齐备

### 生成能力档案

发送：

```text
通读这个工作区里的全部文件，这是一名 2027 届市场营销专业本科生的求职材料。
把它整理成一份能力档案，保存为 能力档案.md，规则如下：

1. 每条能力单独成条，写明判断依据来自哪份文件的哪一段，引用原文关键句；
2. 有具体事实或数字支撑的能力，和只在 self-notes.md 里出现的自我评价，
   分成两个部分，不要混在一起；
3. 全部材料里都找不到佐证的说法，以及材料内部相互矛盾的地方，单独
   列在“存疑”部分，并说明原因；
4. 只做整理和归纳，不要美化，不要替材料补充它没有的内容。
```

## 9.2　分析就业市场（5 张图）

同一会话发送：

```text
我在准备 2027 届校招，目标岗位是内容运营 / 新媒体运营，本科学历。
请同时用 4 个子 Agent 分头上网调研：

1. 主流招聘平台上这个岗位对应届生的任职要求，摘录至少 10 份真实 JD
   的原文要点，注明公司类型、工作城市和学历要求；
2. 这个岗位在一线和新一线城市的薪资范围，以及大厂、内容平台和
   电商公司各自的招聘情况；
3. 近一年这个岗位技能要求的变化，比如 AI 工具、短视频、直播电商
   相关要求的出现频率；
4. 面向 2027 届的校招渠道和时间线，包括秋招提前批的常见节点。

每个子 Agent 都要记录信息来源的网址、发布时间和本次采集日期。只使用
能打开的真实网页；页面要求登录、发布时间不明或信息已经失效时，如实
标注，不要补猜。全部返回后合并成 岗位调研.md，重复内容去重。高频要求
只统计本次收集到的 JD 样本，不把样本结果写成整个市场的普遍结论，并把
JD 原文要点完整保留在文末。
```

若招聘站反复打不开：把自己收藏的 JD 逐份复制成 txt 放进 `job-hunt`，让 dsh 读文件汇总，正文有兜底写法，照常拍图。

- `9-2-02-agent-detail.png`　展开某个子 Agent 的搜索、访问明细
- `9-2-03-research-md.png`　岗位调研.md 的高频要求与来源网址
- `9-2-04-jd-list.png`　文末保留的 JD 原文要点

抽查两条要求的来源网址能打开、没转述走样，然后发送：

```text
读取 能力档案.md 和 岗位调研.md，对照产出一份 差距表.md。
表格四列：岗位要求、现有证据、差距、毕业前来得及做的补救动作。

岗位要求取调研里出现频率最高的条目，按频率从高到低排；现有证据只允许
引用能力档案里有出处的内容，档案里没有的就如实写“无”。频率只按
岗位调研.md 中实际收集到的 JD 样本计算，在表格前写明样本数量，不外推
到整个就业市场。补救动作要具体到能直接执行，比如把哪段经历整理成
带数据的案例、把哪个工具练到能独立出活，不要写“加强学习”这类空话。
```

## 9.3　优化个人简历（8 张图）

依次发送三段，每段等结果再发下一段：

```text
从 岗位调研.md 文末保留的 JD 里，挑出与 能力档案.md 重合度最高的 3 份，
逐份说明推荐理由和主要差距，再把最推荐的一份 JD 原文单独保存为
目标JD.md。
```

- `9-3-01-jd-candidates.png`　3 份候选与推荐理由
- `9-3-02-target-jd.png`　保存下来的 目标JD.md

改简历变成两步，先生成初稿、再对岗优化，依次发送：

```text
根据 能力档案.md 写一份简历初稿，保存为 resume-draft.md。规则如下：

1. 只允许使用材料里已有的事实，禁止编造任何经历，禁止修改或拔高
   任何数字；
2. 经历写成“做了什么、怎么做的、结果如何”，结果优先用材料里已有
   的数字说话；
3. 材料撑不住的能力宁可不写，不要用“沟通能力强”这类没有事实支撑
   的套话凑数；
4. 姓名用材料里的，联系方式一栏留空，由本人自己填；
5. “毛球研究所”从 68450 涨到 83000 是账号整体变化，只能作为兼职期
   间的背景数据，不能写成李小磊一人带来的涨粉成果；
6. 保持单页简历的常规结构，用中文。
```

- `9-3-03-resume-draft.png`　生成的初稿 resume-draft.md。重点看 47 万播放有没有保留，68450 到 83000 有没有被谨慎写成账号整体变化，而非个人独立带来的结果。

```text
读取 resume-draft.md 和 目标JD.md，针对这份 JD 优化出投递版，保存为
resume-new.md。只调整顺序、详略和措辞，把 JD 最看重的经历放到前面
写足，关系不大的压缩；JD 里要求、材料里没有的能力，宁可空着，不要
硬凑；不新增任何事实，不改动任何数字。
```

- `9-3-04-optimize-diff.png`　初稿与优化稿同一段对照，可见顺序详略调整
- `9-3-05-resume-new.png`　resume-new.md 全文

```text
逐句检查 resume-new.md，把核查结果写入 resume-audit.md，不要在
resume-new.md 里添加证据标注。

resume-audit.md 逐条记录简历原句、证据文件和对应段落、核查结论。
没有出处、数字被拔高或把团队及账号整体结果归到个人名下的句子，从
resume-new.md 中删除或收窄；同时在 resume-audit.md 记录修改前后的
内容和原因。完成后确认 resume-new.md 仍是一份不带批注的干净投递稿。
```

- `9-3-06-self-check.png`　resume-audit.md 中的逐句证据核查结果
- `9-3-07-deleted-lines.png`　被删句子清单（若没删，拍“全部有出处”的结论）

导出前先发送下面这段，给演示简历补上虚构联系方式。

把 resume-new.md 里的联系方式补成电话 138-0000-0000、邮箱

确认具备能力后，

## 9.4　模拟求职面试（4 张图）

1. 保持 **Standard mode**，在 `job-hunt` 工作区新建一个会话，发送：

```text
这次会话用来模拟校招面试，请按下面的规则进行：

1. 你是一家互联网公司内容运营团队的负责人，正在面试 2027 届校招生，
   语气专业、克制，不闲聊；
2. 先读工作区里的 目标JD.md、resume-new.md 和 resume-audit.md，确认
   文件读取成功后直接问第一个问题，所有问题围绕这些材料展开；
3. 一次只问一个问题，根据回答追问，追问要扣住简历里的具体经历和
   数字，比如数据怎么统计的、选题怎么想出来的、结果里有多少是
   本人的贡献；
4. 不主动给答案，不在面试中途点评对错；
5. 收到“面试结束”后停止提问，输出一份复盘报告，逐条评价刚才的
   回答，指出哪些答得扎实、哪些暴露了简历撑不住的地方，并给出
   改进建议，把报告保存为 面试复盘.md。
```
