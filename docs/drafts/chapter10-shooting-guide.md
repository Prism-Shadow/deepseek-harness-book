# 第 10 章实操与截图指导（与 book/chapter10.md 逐步对应）

照此文档从上往下操作即可，提示词都是正文里的原文，直接复制粘贴。行情、信号、回测和 headless 兜底已在写作机上跑过，Web 端的界面表现与 schedule 提醒仍以这次实测为准。截图存到 `book/assets/chapter10/`，文件名照写。除了截图，请顺手记录每一步 dsh 的实际表现，包括它汇报的数字、追问、报错和重试，后续用来回填正文里的「待实测」。

## 准备

1. 先运行 `npx -y @deepseek-ai/dsh --version` 和 `which npx`，记下 dsh 版本及 `npx` 的绝对路径，后面的 cron 示例会用到。
2. 运行 `npx -y @deepseek-ai/dsh web`，浏览器打开它打印的地址。
3. 单击左侧 **Workspaces** 旁的 **Add workspace**，新建文件夹 `a-share-research` 作为工作区。
4. 选中该工作区，新开一个会话，确认是 **Standard mode**。

```text
的日期和收盘价。先不要做任何分析。
```

## 第二步　数据体检（对应 10.1 第二段提示词）

发送：

```text
对 data/index_daily.csv 做一次数据检查，逐项确认，日期有没有重复或乱序、
数值字段有没有缺失或明显异常、相邻交易日之间有没有可疑的大缺口，注意
区分节假日的正常空档和真正的数据缺口。

另找一份覆盖数据日期范围、并且更新到当前日期的中国内地股市交易日历，
记录日历来源和获取日期，再用它核对 CSV 是否缺少本应开市的日期。若只能
找到已经停止更新的日历，就把超出覆盖范围的日期标成“无法判断”，不要
仅凭星期一到星期五推断交易日。

把检查过程、日历来源和每一项结论写成 data/数据检查.md。不要修改数据，
只汇报。
```

## 第三步　让 dsh 复述规则（对应 10.2 第一段提示词，同一会话继续）

发送：

```text
接下来把一条经典的双均线方法变成可以检验的规则。原始想法是，短期均线
上穿长期均线说明市场转强，下穿说明转弱，短期用 20 日，长期用 60 日。

先不要写代码。把这个想法复述成一条精确的规则，说清楚均线用哪个价格、
按什么方式计算，"上穿"和"下穿"的确切判定条件是什么，信号记在哪一天。
我没说清楚、需要我拍板的地方，列出来问我。
```

它大概率会列出几个待确认点问你（CLI 实测它问了六个，逐条对应如下）。回复时按这套口径拍板，与正文口径一致：

- 价格用收盘价（它会提典型价备选，不采用）；
- 简单移动平均，窗口含当日；
- 上穿判定为前一交易日短均线小于等于长均线、当日短均线大于长均线；下穿判定为前一交易日短均线大于等于长均线、当日短均线小于长均线。当日两线相等时不产生信号，前一日相等、次日拉开时仍可构成穿越；
- 信号记在穿越发生的当天（收盘后确认）；
- 成交时点它可能建议用次日开盘价，回答用次日收盘价（正文 9.3 回测就是这个口径，别顺着它的建议走）；
- 只做多不做空，先不计交易成本和滑点（这两条 9.3 的回测提示词里也会再写一遍）。

拍图：

- `10-2-01-rule-restate.png`：dsh 的复述回复，最好能看到它列出的待确认点。

记录给我：它问了什么、你怎么答的。

## 第五步　回测（对应 10.3 提示词，同一会话继续）

发送：

```text
对 signals/信号清单.csv 做一次历史回测，信号定义以 signals/规则定义.md
为准，行情数据用 data/index_daily.csv，回测规则如下。

只做一个方向，出现向上信号后，从信号次日的收盘价开始计入持有，直到
向下信号出现后的次日收盘价结束，其余时间空仓。不考虑交易成本和滑点，
每段持有都用全部资金模拟，资金在各段之间连续滚动。

以 60 日均线第一次有完整窗口的日期作为评估起点，策略和基准都在这一天
把净值设为 1，并使用完全相同的截止日期。策略在第一个向上信号出现前
保持空仓，空仓期净值不变。若截止日仍在持有，用最后一个收盘价计算期末
净值，并在报告里标注这是一段尚未出现退出信号的持有。

统计以下内容，持有段数、每段的涨跌幅、上涨段占比、全程累计净值、最大
回撤，并和同期从头持有到尾的基准做对比。把统计结果和一张净值对比图
整理成 backtest/回测报告.md，图片保存在 backtest/ 目录下。

报告结尾单独加一节，列出这条规则表现最差的两三个时间段，说明当时的
行情是什么样子。只根据价格和均线数据描述行情形态；若要解释宏观或政策
原因，必须补充可核对的来源，否则不要猜原因。
```

拍图与取图：

- `10-3-01-backtest-report.png`：dsh 汇报回测结果的回复（持有段数、上涨段占比、累计净值、最大回撤等数字要在画面里）。
- `10-3-02-equity-curve.png`：把 `backtest/` 下的净值对比图产物直接复制过来改名（不用截屏）。

记录给我（最重要的一批数字，正文解读全靠它）：持有段数、上涨段占比、策略累计净值、基准累计净值、最大回撤，以及报告列出的最差时段和它的说明。把 `backtest/回测报告.md` 全文发我最好。

写作机以前跑出的结果不能当成本次答案。结果好看或难看都照实记录；如果和旧结果差很多，先核对数据截止日、评估起点、期末持仓和基准区间，不要为了对上旧数字改口径。

## 第六步　挂载 schedule 插件（对应 10.4 第一小节）

1. 关掉 dsh（终端 Ctrl+C）。
2. 打开 `~/.dsh/profiles/web/cordis.patch.yml`（`$DSH_HOME` 默认就是 `~/.dsh`），在文件末尾追加：

```yaml
- insert:
    - id: schedule
      name: '@deepseek-ai/dsh-schedule'
```

3. 重新运行 `npx -y @deepseek-ai/dsh web`，回到 `a-share-research` 工作区，**新开一个会话**。
4. 顺手帮我验证一条待确认项：先恢复打开之前的旧会话，发一句「列出当前所有定时提醒」，看它有没有 schedule 工具可用，记录结果；然后回到新会话继续。
