# 初识 dsh {#ch-1}

本章启动 dsh 并接入 DeepSeek，用一次真实调用验证配置，再让它在指定文件夹里创建文件。任务完成后，我们查看文件内容和执行记录，核对回复与实际改动是否一致。

## 安装 dsh 并接入模型 {#sec-1-1}

### 准备 Node.js

在终端运行 `node -v`，查看本机的 Node.js 版本。dsh 支持 22.19 及以上的 22.x 版本，也支持 24 及以上版本，23.x 不在支持范围内。

如果终端找不到 `node`，或者版本不符合要求，请从 [Node.js 官网](https://nodejs.org/)安装 LTS 版本。安装完成后重新打开终端，再运行一次 `node -v`。

### 启动 dsh

```sh
npx -y @deepseek-ai/dsh web
```

第一次运行时，`npx` 会从 npm 下载 dsh。启动完成后，终端会打印访问地址，通常是 `dsh web: http://127.0.0.1:3080`。在浏览器中打开这个地址即可进入主界面。

### 接入 DeepSeek

首次启动且尚未配置模型时，页面会要求添加 API 密钥。

```{=latex}
\begin{center}
\begin{minipage}{\linewidth}
\centering
```

![](assets/chapter1/1-1-02-add-key-dialog.png){width=78%}

```{=latex}
\captionof{figure}{尚未配置模型时，dsh 会提示添加一个 API Key}
\end{minipage}
\end{center}
```

如果还没有密钥，请先到 DeepSeek 官方平台创建。将密钥填入对话框，点击“保存并继续”。保存后，页面不会再显示密钥明文。

在“设置”的“模型”页面中，DeepSeek 旁边会出现绿色状态点。它只表示密钥已经保存，不能证明密钥有效，因为保存时 dsh 不会调用模型。需要更换密钥时，点击 DeepSeek 右侧的“编辑”并填入新值。

### 完成第一次调用

点击“选择工作区”，选一个允许写入、也方便检查内容的文件夹。工作区确定后，会话输入框才会启用。本章示例使用 DeepSeek-V4-Flash，推理等级设为 Max。

> 你好，请用一句话介绍你自己

模型返回回复后，消息流中还会出现“上下文注入”和“Think”。它们与 dsh 组织上下文和驱动模型的方式有关，第二部分再详细说明。

![DeepSeek-V4-Flash 返回回复，页面同时显示耗时和 token 统计](assets/chapter1/1-1-08-hello-reply.png){width=86%}

输入框下方的状态栏给出了轮次、步骤、耗时和 token 用量。能够收到回复并看到这组统计，说明从 Web 界面到模型服务的调用已经成功。密钥无效或网络连接失败时，页面会直接显示错误。

## 交给 dsh 第一个任务 {#sec-1-2}

> 帮我在这个文件夹里新建一个 about-dsh.md，写清楚 dsh 是什么、能做什么，两三段就行，不用太长。全文统一写作小写 dsh。

要求已经足够明确，dsh 直接调用 `Write` 创建文件。写入完成后，它在回复中概括了三段内容，并在“产物”区域列出 `about-dsh.md`。

回复只能说明任务已经结束。文件是否真的出现、写入内容是否符合要求，还要继续查看工具记录或直接打开文件。

## 分析 dsh 的执行轨迹 {#sec-1-3}

展开消息流中的“Write · about-dsh.md”，可以看到新增文件的完整差异。这次写入增加了七行，页面以绿色标出新增内容。

![展开 Write 记录后，可以看到 about-dsh.md 的完整写入差异](assets/chapter1/1-3-01-tool-detail-write.png){width=82%}

文件开头如下。

```md
# 关于 dsh

dsh（DeepSeek Harness）是一个本地运行的智能体运行环境，通过网页界面与用户交互。
```

这里的标题和正文都使用了小写 `dsh`，与任务要求一致。回复中提到的三段结构，也能在实际文件里找到。

“Write”记录适合核对文件改动。想查看任务从接收消息到结束的完整过程，可以打开旁边的“轨迹”标签。每一步使用的模型和耗时、工具参数及返回值都按顺序保存在这里。遇到回复与文件不一致，或者任务中途失败时，可以沿着轨迹找到对应步骤。

需要把整段记录留作之后检查时，点击对话顶部的“Session log”即可导出。
